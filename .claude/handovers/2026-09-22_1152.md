# 引き継ぎノート 2026-09-22 11:52

## 今回やったこと

- Kindle Oasis 第9世代の内蔵ブラウザ向け表示プロトタイプを実装（Node.js + sharp）
  - 全画面画像表示 / 定期更新 / 時刻表示の 3 要件
- 第1段階: JavaScript を使わない meta refresh 方式で実装し、headless Chrome で検証（コミット済み）
- 第2段階: ユーザー要望により JavaScript ポーリング方式へ転換（未コミット分）
  - サーバーが版番号 `revision` を持ち、`UPDATE_SEC` ごとに進める
  - クライアントは `POLL_SEC` ごとに `GET /revision` を問い合わせ、番号が変わったときだけ画像を差し替える
  - `src/viewport.js`（CSS プローブ）を削除し、ビューポート実測を JavaScript に一本化
- headless Chrome で実時間 22 秒の検証を実施。更新間隔ごとに画像取得 1 回、その間のポーリングは `/revision` の数バイトのみ、エラー 0
- **実機（Kindle Oasis 第9世代）で問題なく動作することをユーザーが確認済み** → 内蔵ブラウザで JavaScript / XMLHttpRequest / setInterval が動作する

## 決定事項

- **更新方式はポーリング**。`GET /revision` が数字だけを返し、変化時のみ画像を取得する
- **ページ全体のリロードはしない**。`<img>` の `src` だけを差し替える
- **差し替えは `new Image()` でプリロードしてから**。読み込み完了後に `src` を入れ替えるので、切り替え時に白い画面を挟まない
- **クライアント JavaScript は ES5 のみ**。`var` と `XMLHttpRequest` だけを使い、`let`/`const`/アロー関数/`fetch`/`Promise` は使わない（内蔵ブラウザが古い WebKit のため）
- **ビューポートはクライアントが実測**。`document.documentElement.clientWidth/clientHeight` をリクエストに載せ、サーバーはその画素数ぴったりの画像を描く
- 初回画像の `src` は HTML に直接埋め込む（既定 1264 x 1680 px）。JavaScript が動かない環境でも静止画としては表示され、その事実自体が判定材料になる
- **画像に JS 稼働状況を描画する**。`js poll #N errors E last Xs ago` / `js poll: none yet -- javascript may be disabled`。実機に PC を繋がずに JavaScript の可否を判断するため
- 画像は SVG を組み立てて sharp で 16 階調グレースケール PNG に変換（e-ink 向けに白背景・黒描画）
- キャッシュ回避は URL の毎回変わるトークン + `Cache-Control: no-store`
- 設定は環境変数 `PORT`(3000) / `UPDATE_SEC`(30) / `POLL_SEC`(5)

## 捨てた選択肢と理由

- **meta refresh 方式** — 実機で JavaScript が動くことが確認できたため不要。ページ全体を取り直すので通信量が多く、e-ink の全面再描画も毎回発生する。AGENTS.md の方針に従い、フォールバックとして残さず削除した
- **CSS メディアクエリによるビューポート実測（`src/viewport.js`）** — JavaScript での実測の方が正確かつ短い。JS が動く以上は二重に持たない
- **更新時に `location.reload()`** — HTML とスクリプトを毎回取り直し、ポーリングのループも作り直しになる。JavaScript を使う意味が薄れる
- **`<img srcset>` によるビューポート判定** — 2017 年の Kindle ブラウザが srcset に対応している保証がなく、DPR も絡んで不確実
- **画像生成を自前実装（zlib で PNG を手書き）** — 依存ゼロにはなるがフォント描画を自作することになる。sharp（SVG → PNG）は prebuilt バイナリで動き、実データ表示に進む際の表現力も確保できる
- **`node-canvas`** — ネイティブビルドが必要。sharp の prebuilt で足りる

## ハマりどころ

- **CSS 背景プローブが読み込まれない**（第1段階）— `html`/`body` の背景画像は全画面 `<img>` に完全に隠れるため、Chrome が取得を省略した。最前面に置いた 1px の要素に載せ替えて解決（この経路は第2段階で削除済み）
- **headless Chrome の `--virtual-time-budget` では revision の変化を検証できない** — 仮想時間はブラウザ側のタイマーだけを早送りし、サーバーの `setInterval`（実時間）は進まない。`--user-data-dir` を付けてブラウザを起動したまま実時間で 22 秒放置して検証した
- **meta refresh + `--virtual-time-budget` で Chrome が終了しない** — ナビゲーションのたびに予算が再設定されるらしく、無限ループになる。タイムアウトで打ち切った
- **npm が install スクリプトをブロックする** — `sharp` の postinstall が実行されないが、prebuilt バイナリは optionalDependencies 経由で入るため動作に支障なし（`sharp ok 8.17.3` で確認済み）
- SVG の `textLength` は librsvg の対応が不確実なので使わず、等幅フォントの字幅 0.6em からフォントサイズを逆算して行幅を収めている

## 学び

- Kindle Oasis 第9世代の内蔵ブラウザは JavaScript / XMLHttpRequest / setInterval が動作する（実機確認済み）。ただし ES5 前提で書く必要がある
- 「実機で何が動いたか」を画面そのものに描いておくと、PC を繋がずに判定できる。プロトタイプでは有効
- sharp は SVG 入力で日本語（Hiragino Sans）も等幅フォントも問題なく描画できる
