## 決定事項

- **Google カレンダーは iCal 非公開 URL で取得**（ユーザー選択）。OAuth もトークン更新も不要で、ぴよログの feed URL と同じ扱いにできる。繰り返し予定の展開は `ical.js` でこちら側が行う
- **版番号はデータ駆動**。表示内容の JSON が変わったときだけ上げる。電子ペーパーの書き換えを最小化する
- **取得元は名前 + `type`**。`sources.piyolog` のような種別直書きは廃止。項目は名前で指し、省略時はその種別の最初の 1 つ
- **設定の読み直しは取得元ごとの差分で**。レイアウトを直すたびに外部へ取りに行くと、ぴよログの「1 分に 1 回まで」をすぐ超える
- **設定に誤りがあれば読み直しを見送り、動いている設定のまま続ける**。理由はログに出す
- **`--orientation` は起動引数**（設定ファイルではない）。端末の物理的な置き方は再起動を伴う性質のもの
- **`padding` は「読む向き」の上下左右**。回転後ではなく、レイアウトと同じ座標系。マーカーも同じ向きで描かれる
- **`match` の判別は `/.../` の有無**。`type: regexp` のような明示指定より設定が短く済む
- **フォントは等幅 0.6em / 和文 0.55em で字幅を見積もる**。`textLength` は librsvg の対応が読めないので使わない
- **項目は自分の設定の検証・表示内容の組み立て・描画を持つ**（`normalize` / `build` / `render`）。項目どうしは互いを知らない
- **エラー表示は項目の中に出す**。フィードが取れていなければ「ぴよログを取得できません」等をその項目に描く

## 捨てた選択肢と理由

- **Google Calendar API (OAuth リフレッシュトークン)** — 繰り返し予定が `singleEvents` で展開済みに返り反映も即時だが、GCP プロジェクト・OAuth 同意画面・初回認可フローの手作業が必要。個人のダッシュボードには重い
- **`node-ical`** — RRULE の展開を自前で書くことになる。`ical.js` の `ICAL.Event#iterator` + `getOccurrenceDetails` なら差し替え（RECURRENCE-ID）も EXDATE も面倒を見てくれる
- **`zod` による設定検証** — 日本語で「どの項目が悪いか」を出したかった。項目ごとに `normalize` が自分の設定を検証する形にしたので、手書きでも短く収まった
- **`config.js` に取得元の選択ヘルパーを置く** — `config.js` が `widgets/index.js` を import しているので循環する。`validate.js` に `asSourceNames` として置いた
- **ステータス行（更新時刻・フィードの鮮度）を画面下部に常設** — 更新時刻も鮮度も毎分変わるので、データ駆動の版番号判定が毎分発火して意味を失う。エラーは該当項目の中に出す方式にした
- **`fs.watch` による設定監視** — プラットフォーム差とイベントの重複がある。ティックごとの `statSync` で十分かつ確実
- **`padding` とは別に「端末補正用マージン」を設ける** — 同じ計算をする設定が 2 つ並ぶ。`padding` を辺ごとに受け取れるようにして 1 つに統合した
- **表示領域の自動補正** — 端末が実際の表示領域を返さない以上、測る手段（`--markers`）と詰める手段（辺ごとの `padding`）を用意するのが正直な解

## ハマりどころ

- **`ICAL.Time#toJSDate()` は日付のみ・浮動時刻をシステムのローカル時刻で解釈する**。終日の予定が表示タイムゾーンとずれる。`time.isDate || time.zone === ICAL.Timezone.localTimezone` を見て、自前の `fromZoned()` で組み立てる必要がある
- **ICS ファイル内の `VTIMEZONE` を `ICAL.TimezoneService` に登録しないと TZID 付きの時刻が解決できない**
- **等幅フォントの字幅見積もりが 0.55em では足りない**。予定一覧の長い日付行で時刻と件名が重なった。等幅は 0.6em、和文フォントの欧文は 0.55em と分けた
- **`formatRemaining` は目標時刻から数えるので、分の境目は壁時計の分の境目と一致しない**。テストで「同じ分の中なら版番号が上がらない」を確かめるときは、基準時刻を境目からずらす必要がある
- **`png({ colours: 16 })` はパレット PNG を出すので `metadata().channels` は 3**。グレースケールの確認は `stats()` の各チャンネルの平均が一致するかで見る
- **`renderScreen` に `padding` を数値のまま渡しても落ちない**。SVG の座標が `NaN` になるだけで librsvg は無視するため、テストが素通りしてしまった。画像サイズの検証を足した
- **取得元を直接 `delete` するテストと、設定を読み直すテストは挙動が違う**。前者は項目が指す名前がそのまま残る。後者は `normalize` が「そのような取得元はありません」で弾く

## 学び

- ぴよログ データフィードは**スナップショットであって差分ではない**。`event_id` が同じでも編集で値が変わる。「一度取得した ID は無視する」処理は編集を反映できない
- ぴよログは**未入力の数値項目を省略する**。`null` や空オブジェクトではなく項目自体が消えるので、0 と解釈してはいけない
- ぴよログはエラー時も 200 以外で返るので、**エラーを「記録 0 件」として扱わない**こと（仕様書に明記がある）
- Google カレンダーの ICS は `STATUS:CANCELLED` の予定も含まれる。除外が必要
- 電子ペーパーでは色ではなく**大きさで情報の主従を付ける**。階調は補足テキストの `#555` 程度に留めると読みやすい
- 一文字だけの表示（`—` など）を領域いっぱいに `fit` させると巨大になる。「データなし」表示は上限を別に決める
