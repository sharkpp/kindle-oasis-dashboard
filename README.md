# MyRealDashboard

Kindle Oasis（第9世代）の内蔵ブラウザに常時表示する、子供の予定ダッシュボード。
次のごはんまでの残り時間、次のミルクの時間、Google カレンダーの次の予定などを、
電子ペーパー向けの 1 枚の画像として描く。

要件と設計の前提は [SPEC.md](SPEC.md) に書いてある。

## 起動

```sh
npm install
cp config.example.yaml config.yaml   # URL と時間を自分のものに書き換える
npm start
```

起動すると、Kindle から開く URL が表示される。

```
MyRealDashboard — 設定 config.yaml / portrait
  http://localhost:3000/
  http://192.168.11.35:3000/
```

Kindle を同じ Wi-Fi につなぎ、ブラウザ（ホーム → メニュー → ウェブブラウザ）で
`http://<PC の IP>:3000/` を開く。

`config.yaml` にはフィードの秘密 URL が入るので、コミットしない（`.gitignore` 済み）。

### 起動引数

`npm start` から渡すときは `--` を挟む（例: `npm start -- --orientation landscape`）。

| 引数 | 既定値 | 内容 |
| --- | --- | --- |
| `-c, --config <path>` | `config.yaml` | 設定ファイルのパス |
| `-p, --port <number>` | `3000` | 待ち受けポート |
| `-o, --orientation <name>` | `portrait` | 端末の置き方（下記） |
| `--markers` | なし | 四隅に位置合わせマーカーと画像サイズを描く |
| `-h, --help` | | 使い方を表示する |

### 端末の置き方（`--orientation`）

| 値 | 回転 |
| --- | --- |
| `portrait` | 0° |
| `landscape` | 90°（時計回り） |
| `portrait-reverse` | 180° |
| `landscape-reverse` | 270° |

横向きを指定すると、縦横を入れ替えて描いてから回す。端末のブラウザが縦のままでも
横長のダッシュボードが出せるので、壁掛けの向きに合わせて選ぶ。上下が逆になったら
`-reverse` の付いた方に変える。

### 表示領域の確認（`--markers`）

端末が返すビューポートと、実際に見えている範囲は一致しないことがある。
`--markers` を付けると四隅に L 字のマーカーと画像サイズを描くので、
Kindle で見て欠けている隅があれば、その辺が切れている。
切れている分は `padding` を辺ごとに指定して詰める。

### 設定の読み直し

`config.yaml` を書き換えると、次の更新のときに自動で読み直す。再起動はいらない。

読み直しでは新旧の設定を比べ、**実際に変わった取得元だけ**を作り直す。
レイアウトや余白を直しただけなら、ぴよログやカレンダーのキャッシュはそのまま残り、
外部へ取りに行くことはない。取得元の URL・取得間隔・タイムゾーンが変わったときだけ、
そのフィードを空から取り直す。取得元が複数あれば、変わったものだけが対象になる。

設定に誤りがあれば読み直しを見送り、動いている設定のまま続ける。理由はログに出る。
起動引数（ポート・置き方・マーカー）は読み直しの対象ではないので、変えるなら再起動する。

## 設定

[config.example.yaml](config.example.yaml) をそのまま雛形にできる。

### 画面全体

| 項目 | 既定値 | 内容 |
| --- | --- | --- |
| `timezone` | `Asia/Tokyo` | 表示に使うタイムゾーン |
| `poll_sec` | `10` | クライアントが更新を確認する間隔（秒） |
| `tick_sec` | `20` | 表示内容を作り直す間隔（秒） |
| `padding` | `24` | 画面の外周の余白（px）。下記 |
| `gap` | `16` | 項目どうしのすき間（px） |

`padding` は数値ひとつなら四辺とも同じになる。辺ごとに指定することもできる。

```yaml
padding: 28
# または、端末で切れる分を詰める
padding: { top: 28, right: 28, bottom: 60, left: 28 }
```

書かなかった辺は既定値の 24 になる。上下左右は回転後の「読む向き」で数える。

### データ取得元（`sources`）

取得元には自由に名前を付け、`type` で種別を選ぶ。同じ種別をいくつでも定義できる。
項目からはこの名前で指す。

```yaml
sources:
  ぴよログ:
    type: piyolog
    url: "https://feed.piyolog.com/v1/feed/24h/FEED_ID/SECRET"
    interval_sec: 300
  かぞく:
    type: calendar
    url: "https://calendar.google.com/calendar/ical/xxxx%40group.calendar.google.com/private-yyyy/basic.ics"
    interval_sec: 600
  ほいくえん:
    type: calendar
    url: "https://calendar.google.com/calendar/ical/zzzz%40group.calendar.google.com/private-wwww/basic.ics"
```

| `type` | 取得元 | 指定する項目 | `interval_sec` の既定 |
| --- | --- | --- | --- |
| `piyolog` | ぴよログの iOS アプリで「設定 → データフィード」から発行した URL | `url` | `300` |
| `calendar` | Google カレンダーの「設定 → カレンダーの統合 → iCal 形式の非公開 URL」 | `url` | `600` |
| `weather` | 気象庁の防災情報 JSON | `area` ほか（下記） | `1800` |

ぴよログの取得は 1 分に 1 回までが目安で、取得期間ごとにキャッシュ保持時間がある
（24h: 1 分 / 3d: 2 分 / 7d: 5 分 / 28d: 15 分）。`interval_sec` はそれ以上にする。
`piyolog` と `calendar` は最短 60 秒、`weather` は最短 600 秒。

#### `weather` の指定

```yaml
  てんき:
    type: weather
    area: "130000"        # 府県予報区のコード（東京都なら 130000）
    sub_area: "130010"    # 省略可。予報区の中の区域（東京地方）
    temp_area: "44132"    # 省略可。気温を取るアメダス地点（東京）
    interval_sec: 1800
```

認証も利用登録もいらない公開ファイルを読む。発表は 1 日 3 回（05 / 11 / 17 時）なので、
短い間隔で取りに行っても内容は変わらない。

- `area` — `https://www.jma.go.jp/bosai/forecast/data/forecast/{area}.json` の `{area}`。
  気象庁のページで府県予報区を開いたときの URL に出てくるコード
- `sub_area` — 同じ予報区の中の区域。省略すると最初の区域（多くは県の主要部）を使う
- `temp_area` — 気温はアメダス地点ごとに出るので、区域とは別のコードになる。
  省略すると最初の地点を使う

週間予報は短期予報より区域のくくりが粗く、指定した区域が無いこともある。
その場合は短期予報の分だけで出す（明後日の降水確率と気温が空になることがある）。

使わない項目しか置いていないなら、その取得元は省略してよい。

### レイアウト（`columns`）

画面をカラムに横分割し、各カラムの中で項目を縦に積む。
`width` と `height` は比率で、端末の画素数に合わせて引き伸ばされる。

```yaml
columns:
  - width: 1          # カラムの幅の比率（既定 1）
    items:
      - type: clock
        height: 3     # カラム内での高さの比率（既定 1）
        date: true
```

### 項目

すべての項目に `type` と `height` を指定できる。`label` は項目の上に出る小さな見出し。

| `type` | 内容 |
| --- | --- |
| `countdown` | 指定の時間までの残り時間。時刻は複数指定でき、曜日でも絞れる |
| `milk` | 次のミルクの時間。ぴよログの直近の記録から指定時間後を目標にする |
| `milk-total` | きょうのミルクの回数と量の合計 |
| `calendar` | 次の予定。複数のカレンダーをまとめられ、件名で絞れる |
| `weather` | 今日・明日・明後日の天気・降水確率・気温 |
| `weather-today` | 当日の天気を書式に沿って出す |
| `clock` | 時刻と日付 |
| `section` | セクションタイトル |

それぞれの設定項目とサンプルは **[docs/widgets.md](docs/widgets.md)** にまとめてある。
新しい項目を足すときの約束もそこに書いてある。

## 仕組み

サーバーは `tick_sec` ごとに、フィードを（取得間隔を過ぎていれば）取り直し、
設定どおりに表示内容を組み立てる。組み立てた内容が前回と一字一句同じなら、
版番号は上げない。クライアントは `poll_sec` ごとに `/revision` を問い合わせ、
番号が変わったときだけ新しい画像を読み込んで `<img>` を差し替える。

- `GET /` — 全画面 `<img>` とポーリング用スクリプトを含む HTML。
- `GET /revision` — 現在の版番号を数字だけで返す。クライアントの実測ビューポートもここで受け取る。
- `GET /screen.png` — SVG を組み立てて sharp で 16 階調グレースケール PNG に変換。
  横向きの指定では、縦横を入れ替えて描いてから回す。

設計上の選択:

- **表示内容が変わったときだけ版番号を上げる** — 電子ペーパーの書き換えを、
  見た目が変わるときだけに絞る。時刻の表示が分単位なら、書き換えも 1 分に 1 回で済む。
- **ページリロードではなく画像の差し替え** — HTML・スクリプトを取り直さない。
  新しい画像を `new Image()` で読み終えてから `src` を差し替えるので、白い画面を挟まない。
- **クライアントは ES5 のみ** — Kindle の内蔵ブラウザは古い WebKit。
  `var` と `XMLHttpRequest` だけを使い、`let`/`const`/アロー関数/`fetch`/`Promise` は使わない。
- **ビューポートはクライアントが実測** — サーバーはその画素数ちょうどの画像を描く。拡大縮小が入らない。
- **取得に失敗しても前回の内容を捨てない** — 失敗は該当する項目に出し、再試行は間隔を伸ばしながら行う。
- **設定の読み直しは取得元ごとに差分で** — レイアウトを直すたびに外部へ取りに行くと、
  ぴよログの「1 分に 1 回まで」という目安をすぐ超える。変わった取得元だけを作り直す。
- **キャッシュは全面的に無効化** — URL に毎回変わるトークンを付け、`Cache-Control: no-store` も併せて送る。

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/server.js` | 起動引数、HTTP サーバー、ルーティング、設定の読み直し |
| `src/config.js` | YAML 設定の読み込みと検証 |
| `src/dashboard.js` | フィードの更新と表示内容の組み立て、版番号の管理、設定の差し替え |
| `src/layout.js` | カラムと項目の配置 |
| `src/render.js` | SVG 組み立て → 回転 → グレースケール PNG |
| `src/page.js` | 全画面 `<img>` + ES5 ポーリングスクリプト |
| `src/sources/` | 取得元の種別と、ぴよログ・カレンダー・天気予報の取得とキャッシュ |
| `src/widgets/` | 組み込みの項目（検証・組み立て・描画）。仕様は [docs/widgets.md](docs/widgets.md) |

## テスト

```sh
npm test
```

固定した日時と固定のフィードデータで、設定の検証・フィードの解釈・各項目の表示内容・
PNG の描画までを確かめる。
